# タスク分解テンプレート

タスクのページ内に以下の構造で書き込む。
状況に応じてセクションの追加・省略は可能だが、基本はこの構造に従う。

---

## ゴール

> このタスクの完成状態を1文で定義する。「何ができたら Done か」を明確に。

## サブタスク

Notion の to-do ブロック（チェックボックス）として書き込む。
`- [ ]` で書くと Notion 上でタップして完了にできるチェックボックスになる。
期限がある場合は逆算して各サブタスクに期限を振る。
各サブタスクは1回の作業セッション（30分〜2時間）で完了できるサイズにする。

- [ ] サブタスク1（期限: MM/DD）
- [ ] サブタスク2（期限: MM/DD）
- [ ] サブタスク3（期限: MM/DD）
- [ ] サブタスク4（期限: MM/DD）
- [ ] サブタスク5（期限: MM/DD）

> スマホの Notion アプリからチェックボックスをタップするだけで完了にできる。

## 必要な情報・リソース

タスクに着手する前に揃えておくべきもの。

- **調べること**: まだ分かっていないこと
- **参考リンク**: 公式ドキュメント、記事、リポジトリ
- **ツール・アカウント**: 必要なツールやサービス
- **人に聞くこと**: 自分では判断できない意思決定

## 調査メモ

Claude が調べた結果や、ユーザーが追加した情報をここに蓄積する。

### 調査1: [トピック]
- 結果の要約
- 参考URL

### 調査2: [トピック]
- 結果の要約
- 参考URL

## 手順

サブタスクを実行する具体的な順序。依存関係がある場合はそれも明示する。

1. **[サブタスク1]**: やること。前提条件があればここに書く。
2. **[サブタスク2]**: やること。サブタスク1の結果を使う場合はその旨記載。
3. **[サブタスク3]**: やること。
4. ...

## メモ・気づき

作業中に出てきたアイデアや注意点をここに追記する。

# テンプレート適用ルール

## 分解の深さ

| ユーザーの指示 | サブタスク数 | 詳細度 |
|--------------|------------|--------|
| 「ざっくり」 | 3つ程度 | 大きな塊 |
| デフォルト | 3〜7つ | 1セッション単位 |
| 「もっと細かく」| 各サブタスクをさらに分解 | 手順レベル |

## 期限の逆算ルール

- 親タスクの期限から逆算し、最終日の **1日前** に全完了する計画にする
- サブタスクの所要時間は種類で推定:
  - 調査・リサーチ: 1〜2時間
  - 資料・コンテンツ作成: 2〜4時間
  - コーディング: 2〜4時間
  - レビュー・修正: 1時間
  - 確認・テスト: 30分〜1時間

## 調査の自動実行

「必要な情報・リソース」で洗い出した項目のうち、
Web検索やコードベース調査で分かるものは Claude が自動で調べて「調査メモ」に書く。
ユーザーに聞かないと分からないものだけ質問する。

### 調査の手順

1. サブタスクと「必要な情報」から調査すべきトピックを特定
2. WebSearch で関連情報を検索
3. 必要に応じて WebFetch で詳細ページを取得
4. 結果を要約して「調査メモ」セクションに追記
5. 参考 URL も一緒に記録

### 調査の対象

- 技術的なベストプラクティス・手順
- ツールの使い方・設定方法
- 競合・参考事例
- API ドキュメント・仕様
- 所要時間の見積もりに必要な情報

### 調査しないもの

- ユーザーの個人的な判断が必要なこと（デザインの好み、ビジネス判断など）
- アカウント情報、認証情報
- 社内の非公開情報
